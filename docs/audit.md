# Аудит BentoPDF — этап 1

Дата проверки: 16 ноября 2026. Основа: форк github.com/yurgon/bentopdf, версия BentoPDF 2.8.11 (upstream: alam00000/bentopdf, ветка main от 14.11.2026).
Как проверял: полная сборка (`npm run build`, режим с внешней сетью доставки), локальный сервер с заголовками изоляции, прогон инструментов в Chrome без окна на своих тестовых PDF (текст, пустые страницы, скан, перекошенный скан, письмо .eml), проверка результатов отдельным скриптом (число страниц, размер, текстовый слой, наличие удалённых слов).

## Коротко

- Набор зрелый: 125 страниц инструментов, 24 языка интерфейса и текстов, своя система SEO при сборке (статические языковые страницы, hreflang, карта сайта, разметка, проверка SEO). Большая часть «технической части» ТЗ уже есть.
- Карты запросов по 10 страницам первой очереди готовы (`docs/seo`), там же спрос по всем инструментам. Предложения отдельных страниц и статей — в конце этого файла.
- Из 20 строк таблицы: 13 работают как есть, 2 работают с важными оговорками (тёмный режим и плакат превращают страницы в картинки), 1 работает с ошибкой на редких страницах (выравнивание), 4 отсутствуют полностью (PDF в EPUB, тестовая страница, миллиметровка, бинго, прописи — пишем сами), DjVu и MOBI — см. ниже.
- Отдельной страницы вымарывания нет: оно живёт внутри редактора. Работает по-настоящему: текст удаляется из файла.
- Сжатие до точного размера уже есть, вместе с готовыми страницами под 100 КБ, 200 КБ, 500 КБ, 1 МБ и 2 МБ.
- Все модули обработки запускаются в Node.js, значит локальный MCP-сервер может использовать тот же код.
- Главные риски: два файла офисного конвертера больше лимита Cloudflare (25 МБ); тексты страниц BentoPDF сделаны по шаблону (одинаковый блок «How It Works» на всех страницах) и упоминают BentoPDF сотни раз, их придётся переписать.

## Текст страниц и переводы в исходном HTML

- **Да, отдаётся статически.** Сборка создаёт 3341 HTML-файл: по отдельной странице на каждый инструмент и язык (`/ru/compare-pdfs` и т. д.). Весь текст, включая вопросы и ответы, есть в HTML без скриптов. Проверено на русской версии страницы сравнения.
- У каждой страницы канонический адрес, 24 hreflang + x-default, robots, разметка JSON-LD, Open Graph. Карта сайта на 137 адресов с языковыми альтернативами. Встроенная проверка `seo-audit.mjs` проходит.
- Важно: по умолчанию канонические адреса указывают на bentopdf.com. Для своего сайта при сборке нужны `SITE_URL=<наш домен>` и `ALLOW_INDEXING=true`, иначе все страницы получают noindex.
- Текст страниц инструментов: около 550 слов, блок вопросов-ответов по делу. Но блок «How It Works» одинаковый на всех страницах («Upload File → Process → Download»), а блок «Related PDF Tools» шаблонный («Free online merge PDF tool»). По нашему ТЗ такие блоки запрещены, страницы первой очереди пишем заново.
- Бренд: переменные `VITE_BRAND_NAME/LOGO/FOOTER_TEXT` меняют шапку и подвал, но в заголовках страниц, текстах и переводах «BentoPDF» встречается сотни раз (только в русском файле текстов 486 раз). Нужна замена при сборке, отдельным модулем.

## Хостинг Cloudflare

- Лимиты Pages (проверено 16.11.2026 на developers.cloudflare.com/pages/platform/limits): файл до 25 МиБ, до 20 000 файлов на бесплатном тарифе, до 100 правил в `_headers`, заголовок до 2000 знаков. В сборке 4730 файлов, 313 МБ — проходит.
- **Не проходят два файла офисного конвертера LibreOffice**: `soffice.wasm.gz` 47 МБ и `soffice.data.gz` 27 МБ. Они грузятся только с нашего сайта, внешней сети доставки для них нет. Решение: положить их в Cloudflare R2 и отдавать с нашего домена через маленький Worker по тому же пути `/libreoffice-wasm/` (тот же источник, заголовки изоляции сохраняются). Запасной вариант: отключить офисные конвертеры до решения.
- Заголовки изоляции: сборка сама пишет `dist/_headers` с `Cross-Origin-Opener-Policy: same-origin` и `Cross-Origin-Embedder-Policy: credentialless`, плюс Content-Security-Policy. Cloudflare Pages читает этот файл. Режим `credentialless` позволяет грузить модули с jsDelivr без особых заголовков у них.
- Модули с внешней сети доставки (jsDelivr): PyMuPDF, Ghostscript, CoherentPDF, Tesseract и языковые пакеты. В тесте OCR пакеты загрузились с jsDelivr при включённой изоляции — работает. Запасной вариант: скрипт `prepare-airgap.sh` скачивает все модули, их можно разместить на своём домене (R2 + Worker), переменные `VITE_WASM_*`, `VITE_TESSERACT_*` уже есть. Важно: модули должны быть с того же источника или с CDN, который отдаёт их по CORS.
- В репозитории уже есть `cloudflare/wrangler.toml`, `wasm-proxy-worker.js` и прокси CORS для цифровой подписи (сейчас указывает на сервер BentoPDF: `bentopdf-cors-proxy.bentopdf.workers.dev` — нужно поднять свой или отключить).

## Внешние запросы и приватность

- Google Fonts (fonts.googleapis.com / gstatic) — передаёт адрес посетителя Google. Для «без сторонних трекеров» лучше разместить шрифты у себя.
- Счётчик звёзд GitHub — отключается `DISABLE_GITHUB_STARS=true`.
- Реклама: в коде есть рекламный блок, но он включается только на bentopdf.com (`showAds`). У нас выключен.
- Шрифты для редактора и OCR-слоя грузятся с jsDelivr и rawcdn.githack.com (Noto). Файлы пользователя не уходят никуда — проверено по сетевым запросам при OCR.

## DjVu в PDF и EPUB в MOBI

- **DjVu → PDF: выполнимо в браузере.** Есть свежая библиотека `djvu-rs` (MIT, Rust → WebAssembly, обновлена 12.11.2026, 1,4 МБ): открывает и рисует страницы DjVu в браузере и Node. Схема: страницы в картинки → PDF (pdf-lib), скрытый текстовый слой из DjVu, если он есть, иначе OCR по желанию. Есть и старый DjVu.js (`djvujs-dist`, 21 МБ, без указанной лицензии в npm — не брать). Качество: страница-картинка, как в исходнике. Рекомендация: делать во второй очереди.
- **EPUB → MOBI: технически выполнимо только своим кодом, не рекомендую.** Готовой библиотеки, которая пишет MOBI в браузере, нет (есть только читатели MOBI). Писать свой генератор MOBI — недели работы. При этом Amazon с 2022 года не принимает MOBI через Send to Kindle и сам принимает EPUB. Спрос 4 400 в месяц в основном от старых привычек. Предлагаю вместо этого страницу «EPUB на Kindle» с объяснением, что конвертация больше не нужна.

### Как собраны карты и ограничения

- Сначала брал главный запрос из ТЗ и его похожие запросы. Затем около 40 вариантов с типичными уточнениями и вопросами из выдачи, затем их похожие, и так далее, пока запросы оставались в теме. Всего около 12 тысяч проверенных запросов, в картах — от 238 до 1 710 запросов на тему.
- Совпадение выдачи сервис даёт только с прямыми соседями (до 10 на запрос). Для остальных оно оценено через общих соседей и отмечено в картах знаком «≈». Если совпадение неизвестно, решение принято по смыслу и отмечено в пояснении.
- Близкие формулировки ведут на одну и ту же выдачу, поэтому показы внутри карты складывать нельзя.
- У сервиса суточный лимит: 10 000 новых запросов в день. Сегодня он почти исчерпан, поэтому сбор остановлен на собранном (этого хватает). Повторные проверки идут из кэша бесплатно.

## Спрос по всем инструментам BentoPDF (для второй очереди)

Полная таблица по 118 инструментам — `docs/seo/tools-demand.md`.

Больше всего показов: PDF Editor и PDF to Word (по 246 000), JPG to PDF (201 000), PDF to JPG (165 000), Merge (135 000), Compress и Word to PDF (по 110 000), PNG to PDF (90 500).

Самый ценный трафик (показы, умноженные на цену клика): PDF Editor, JPG to PDF, PDF to Word, Merge, Compress, PDF to JPG, PDF to PNG, Word to PDF, EPUB to PDF, PNG to PDF, Image to PDF, Create fillable PDF, PDF to Excel, Sign PDF, Split.

Из нишевых, но дорогих: удаление пустых страниц (720), удаление метаданных (1 600), EML в PDF (3 600), нумерация Bates (320, клик $7,16).

У 10 инструментов спрос почти нулевой: метки страниц, коррекция цвета, PDF для ChatGPT, чередующееся слияние, сборка двустороннего скана, вложения, поворот на произвольный угол, PDF в ZIP, линеаризация, кривые из текста. Их страницы стоит оставить без отдельного продвижения или объединить с соседними.

Требуют проверки: у 8 инструментов сервис предлагает «более сильную формулировку с той же выдачей», но спрос у неё подозрительно выше. Например, «booklet creator» 90 500 для брошюры, «pdf/a converter» 110 000, «poster print» 49 500, «fill pdf» 74 000. Совпадение выдачи у таких пар часто держится на крупных сайтах PDF-инструментов, а не на одинаковом смысле. Их проверяем по выдаче, прежде чем менять главные запросы. Отмечены знаком ⚠ в таблице.

Расхождение: в таблице инструментов «compare pdf» показан с нулевым спросом, а в карте сравнения у «compare pdfs» 5 400. Правильная цифра — из карты: сервис по-разному считает формы с «s» и без.

## Заметки на следующий этап

- Папка `docs/` в BentoPDF — это ещё и исходник сайта документации (VitePress). При сборке документации аудит, лицензии и карты нужно исключить (`srcExclude`) или перенести в отдельную папку.
- Скрипты сбора и классификации запросов пока лежат во временной папке сессии. Если нужно повторять сбор на другие страны и языки, перенесу их в репозиторий (`tools/seo`) без ключа доступа.
